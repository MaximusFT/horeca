# 1. Product definition

> **An AI-assisted procurement manager for a small HoReCa business that continuously combines normal restaurant demand, upcoming catering/events, recipes, inventory and incoming stock into an up-to-date procurement plan, then turns that plan into supplier-ready orders.**

The system answers:

1. **What should we buy?**
2. **How much should we buy?**
3. **When should we buy it?**

Then it helps execute the purchase through a connected supplier.

For the hackathon, the first connected supplier is **Silpo through its official MCP**.

---

# 2. Core product insight

The product is **not “repeat my previous basket, but smarter.”**

It is a continuously recalculated future procurement plan with two demand sources:

## 2.1 Regular restaurant operations

Recurring baseline consumption produced by normal restaurant activity.

For the MVP this is deterministic: a NORMAL daily profile multiplied by a day load factor.

## 2.2 Catering / event demand

Known future demand generated by explicit events, guest counts, menus and recipes/BOM.

## 2.3 Conceptual formula

```text
Procurement Need
=
Regular Restaurant Demand
+
Event / Catering Demand
+
Safety Stock
-
Current Inventory
-
Confirmed Incoming Supply
```

The actual engine must be **chronological**, not a single period-total subtraction.

A wrong engine would calculate 14-day salmon demand, subtract stock, and buy everything today.  
A correct engine understands timing, expiry and incoming supply.

**Procurement / Operations Manager**

In a small business this may be:

# 17. Deterministic vs AI responsibilities

## Deterministic code owns

- all arithmetic;
- recipe/BOM expansion;
- unit conversion;
- event demand;
- restaurant demand;
- aggregation;
- timing;
- FEFO;
- incoming supply;
- safety stock;
- shortage;
- procurement dates;
- batch consolidation;
- package rounding;
- cost from actual supplier package counts;
- plan diff;
- demand provenance.

## AI owns

- natural-language understanding;
- tool choice;
- explanation;
- helping resolve supplier-product mappings;
- evaluating replacement candidates;
- proposing actions;
- orchestrating supplier steps.

## AI must never

- invent stock/prices/availability;
- become the calculator;
- silently mutate state;
- bypass approval;
- automatically pay/order without human confirmation.

# 18. Procurement engine requirements

Pipeline:

```text
restaurant calendar + events
→ raw demand
→ recursive BOM
→ normalized units
→ requiredAt
→ ingredient timeline
→ FEFO inventory
→ confirmed incoming
→ safety target
→ shortage
→ procurement delivery scheduling
→ planned supply injection
→ future projection
→ compatible batch consolidation
→ supplier enrichment
→ packages/cost
→ exceptions
```

## Mandatory chronology

Planned procurement becomes future supply and must be injected back into projection.

Planned stock also has shelf life.

This prevents:
- duplicate shortages;
- buying perishables too early.

## Safety stock

Safety stock is a target balance, not extra demand added at every time point.

## MVP delivery heuristic

```text
Shelf life <=3 days → target requiredAt - 1 day
4–7 days           → target requiredAt - 2 days
8–30 days          → may consolidate ~4 days early
>30 days           → may consolidate ~7 days early
```

A greedy consolidation algorithm is sufficient.

- Overview understandable without narration.
- One click explains any purchase quantity.
- Wedding 180→200 visibly changes the plan.
- Supplier issue becomes actionable rather than a dead end.

## Engine
- recursive BOM;
- circular guard;
- event + restaurant demand;
- unit normalization;
- FEFO;
- incoming timing;
- safety target;
- chronological scheduling;
- planned supply injection;
- package rounding;
- deterministic plan diff;
- no duplicate procurement.

## Agent
- uses preview;
- waits for approval;
- uses same use cases as UI;
- does not invent calculations;
- explains engine provenance.

## MCP
- server-side OAuth;
- `tools/list`;
- cart context;
- product search;
- one test write;
- cart reread;
- replacement flow if possible.

# 36. Human summary

> **HoReCa Procurement Agent is a procurement cockpit for a restaurant with catering. It knows what the restaurant normally consumes, what future events require, what is already in stock and what is already on the way. It continuously builds a dated purchasing plan, explains every quantity, resolves supplier problems, and prepares supplier orders. Silpo is the first connected supplier through MCP, not the entire product.**
