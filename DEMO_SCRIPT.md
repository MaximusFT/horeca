# HoReCa Procurement Agent — Demo Script (≈5:00)

Формат: **Слова** — те, що говориш (українською). **Дії** — що робиш на екрані (російською, для точності кліків).

Передумова перед репетицією: `npm run dev`, відкрити `http://localhost:3000/overview`, натиснути **Reset demo** (Wedding = 180, Plan v1, порожня тестова корзина).

**Фінальний відеопітч не записувати, доки live MCP не підтверджено.** Перед фінальним записом `/debug/mcp` має показати успішний OAuth, реальний `tools/list` і щонайменше один успішний офіційний tool call. Якщо в кадрі видно `Тестовий постачальник` або `mock cart`, не називати це підключеним «Сільпо».

Для фінального запису не покладатися на вкладку Chrome DevTools MCP: виклики до `mcp.silpo.ua` виконуються server-side у Vercel, а не як WebMCP tools сторінки. DevTools Network покаже browser → Next.js (`/api/agent/messages`, `/api/suppliers/*`, `/api/silpo/trace`). Доказом офіційних server-side MCP-викликів у кадрі є нумерований блок **Виконання запиту агента** з позначками **Застосунок** і **Silpo MCP**.

## 03:40–04:45 · Один запит агенту → перевірений кошик Silpo

**Слова:**
> «Тепер я не переходжу між технічними екранами. Я ставлю агенту одну бізнес-задачу: підготувати найближче замовлення постачальнику і перевірити ризики. Агент читає детермінований план, перевіряє реальний кошик і доставку, шукає товари та ризики заміни через офіційний Silpo MCP. Усі кроки зʼявляються в журналі виконання. Спочатку я переглядаю результат. І лише окремим підтвердженням дозволяю змінити кошик.»

**Дії:**
На `/procurement` открыть **Procurement Agent**. Ввести или выбрать **Prepare the next supplier order**. Пока запрос выполняется, показать появление live шагов. После ответа раскрытый журнал должен показать: `Read procurement plan` → `Read active Silpo cart` → `Read and verify Silpo cart` → `Validate Silpo delivery slot` → `Search Silpo products` → `Check Silpo replacement risk` → `Prepare supplier order`. Показать `Live-пілот: 3 із N`. Нажать **Переглянути кошик**. Сделать паузу на preview и отдельной кнопке подтверждения. Для финального дубля подтвердить запись только при чистой тестовой корзине. Показать новые MCP steps: `Write approved products to Silpo cart` → `Read and verify Silpo cart`, затем зелёный verified state.

## Нотатки перед записом

- Перед стартом обов'язково натиснути **Reset demo**, інакше стан буде «брудний» від попередніх прогонів.
- Якщо записуєш кілька дублів — щоразу повторюй Reset demo.
- Не показувати `/debug/*` сторінки в кадрі — вони для розробки, не для демо.
- Перед дублем з реальною cart mutation вручну прибрати попередні тестові товари з кошика Silpo. **Reset demo** не очищає реальний кошик.
- Якщо щось піде не так наживо (наприклад, лосось випадково вже замінений) — це нормально виправляється через Reset demo, а не ручним відкатом.
